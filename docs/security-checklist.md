# 碰钱代码上线清单（策划书第六章）

| 要求 | 现在的做法 | 状态 |
|---|---|---|
| 私钥、助记词、API 密钥不出现在代码、日志、数据库、报错里 | 钱包由 bnbagent SDK 的 Turnkey / 加密 keystore 持有；token 只走环境变量；`config/policy.json`、`config/chain.json`、`data/` 都在 `.gitignore` | ✅ |
| 金额用整数最小单位或 Decimal，不用浮点 | `to_amount` 拒绝 float；链上用 `to_base_units` 精确换算，需要舍入就报错；数据库存文本 | ✅ 有测试 |
| 每笔付款唯一编号，同一编号绝不付两次 | 编号 = Telegram 群 ID + 消息 ID；付款前先写账本（主键），重复投递直接拒绝 | ✅ 有测试 |
| 白名单和限额在钱包签名层也配置 | 应用层已检查；签名层要在 Turnkey 策略里配置，主网前必须完成 | ⏳ 等钱包 |
| 模型输出只是建议，放款由规则引擎决定 | 解析器只产出结构化请求，`agent/rules` 决定结果；目前解析器是确定性规则，没接大模型 | ✅ |
| 消息里的「忽略规则」不改变规则 | 规则引擎不读备注；有专门测试 | ✅ 有测试 |
| 所有付款可追溯：谁提交、谁批准、哪条规则放行 | 账本记录提交人、命中的规则、状态、交易哈希、审批人 | ✅ |
| 一键暂停 | Telegram `/pause`、控制台按钮，状态存在数据库，重启后仍然暂停 | ✅ 有测试 |
| 主网保护 | 实盘启动核对链 ID；主网需 `CHAINSTAFF_ALLOW_MAINNET=yes`，且禁止本地私钥 | ✅ 有测试 |
| 发送前模拟 | `eth_estimateGas` 失败（比如余额不足、会回滚）就不签名 | ✅ 有测试 |
| 依赖和代码扫描 | CI 跑 pip-audit 和 Semgrep | ✅ |
